# 图像和视频上传功能问题总结

## 问题 1：手机端构建 OkHttp API 兼容性报错

### 问题现象

Android 项目编译报错：

```
Using 'get(String): MediaType' is an error. moved to extension function
Using 'body(): ResponseBody?' is an error. moved to val
```

### 根因分析

OkHttp 4.x 对部分 API 做了迁移，从静态方法改为 Kotlin 扩展函数和属性：

| 旧 API（OkHttp 3.x） | 新 API（OkHttp 4.x） |
|---|---|
| `MediaType.get("image/jpeg")` | `"image/jpeg".toMediaType()` |
| `RequestBody.create(mediaType, file)` | `file.asRequestBody(mediaType)` |
| `response.body()` | `response.body`（属性访问） |

项目中使用的 OkHttp 版本为 `4.12.0`（`build.gradle:76`），这些旧 API 已被标记为 error。

### 解决方案

在 `MediaUploader.kt` 中改用 OkHttp 4.x 扩展函数：

```kotlin
import okhttp3.MediaType.Companion.toMediaType
import okhttp3.RequestBody.Companion.asRequestBody

// 构造 RequestBody:
file.asRequestBody("image/jpeg".toMediaType())
file.asRequestBody("video/mp4".toMediaType())

// 读取响应体:
response.body?.string()
```

## 问题 2：Web UI 截图 URL 拼接错误导致 404

### 问题现象

服务端 Web 页面显示事件列表，但截图无法加载，浏览器请求返回 `404 Not Found`。

请求 URL 为：

```
http://localhost:8000/api/api/storage/thumbnails/<eventId>/thumb_0.jpg
```

比正确的多了一个 `/api` 前缀。

### 根因分析

前端代码有两处 URL 拼接使用了 `API_BASE + relativePath`：

**`templates/index.html:119`** — 截图 URL：

```javascript
const API_BASE = location.origin + '/api';  // → http://host:8000/api
const thumbSrc = API_BASE + e.thumbnails[0];
// e.thumbnails[0] = "/api/storage/thumbnails/xxx/thumb_0.jpg"
// 结果: http://host:8000/api/api/storage/thumbnails/...  ← 重复 /api
```

**`templates/index.html:130`** — 录像 URL 同样问题：

```javascript
href="${API_BASE}${e.videoUrl}"
// e.videoUrl = "/api/storage/videos/xxx/recording.mp4"
```

服务端 `list_events` API 返回的 `thumbnails[0]` 和 `videoUrl` 已经以 `/api/` 开头（绝对路径），而 `API_BASE` 也包含了 `/api`，拼接后产生双 `/api`。

### 解决方案

去除 `API_BASE +` 前缀，URL 本身已是绝对路径，浏览器会自动解析到正确地址：

```javascript
const thumbSrc = e.hasSnapshot ? e.thumbnails[0] : null;
// ...
href="${e.videoUrl}"
```

## 问题 3：截图上传后服务端文件未保存

### 问题现象

Android 通过 HTTP POST 上传截图，服务端日志显示 `Snapshot saved: ...`，但通过 `GET /api/storage/thumbnails/` 访问时文件不存在。

### 根因分析

服务端上传处理使用了 `shutil.copyfileobj` 在线程池中执行：

```python
loop = asyncio.get_event_loop()
def _write():
    with open(dest, "wb") as f:
        shutil.copyfileobj(file.file, f)
await loop.run_in_executor(None, _write)
```

`UploadFile.file` 是 FastAPI 的 `SpooledTemporaryFile`，该对象不适合在 `run_in_executor` 的线程池中跨线程读取。线程池执行时，文件指针位置未预期对齐或文件句柄状态异常，导致数据未能正确写入。

### 解决方案

改用 `await file.read()` 在异步上下文中直接读取完整内容，再同步写入文件：

```python
content = await file.read()
with open(dest, "wb") as f:
    f.write(content)
```

对于截图 (~200KB) 和录像 (几 MB) 文件，直接读取到内存是可行的。这避免了线程池中读取 `SpooledTemporaryFile` 的不确定性。
