# 熄屏后运动检测不亮屏问题总结

## 问题现象

手机熄屏（锁屏或系统自动休眠）后，摄像头预览画面消失，运动检测失效。即使画面中有运动物体，屏幕也不会自动点亮，导致门铃系统在熄屏后无法正常工作。

## 问题根因

### 根本原因：Preview use case 依赖 UI Surface，熄屏时 CameraX 整条 pipeline 被暂停

相机通过 `ProcessCameraProvider.bindToLifecycle()` 同时绑定 `Preview` 和 `ImageAnalysis` 两个 use case：

- `Preview` — 负责将相机画面渲染到 `PreviewView` 供 UI 显示，依赖 `PreviewView` 的 `Surface`
- `ImageAnalysis` — 负责出帧给分析器做运动和人形检测，无需 Surface

**熄屏时的连锁反应：**

```
屏幕熄灭 → Activity onPause/onStop
  → PreviewView 背后的 Surface 被销毁
    → Preview use case 输出表面丢失
      → CameraX 检测到 bindToLifecycle 中任一 use case 依赖不满足
        → 暂停整个 camera session（包括 ImageAnalysis）
          → analyzer 永不触发 → processFrame 永不调用
            → MotionDetector.detect() 永不运行
              → acquireScreenWakeLock() 永不会被调用
                → 屏幕一直保持熄灭 → 死锁
```

问题的本质是：CameraX 把同一 `bindToLifecycle` 中的多个 use case 视为整体——任一 use case 的依赖（这里是 Preview 的 Surface）不满足，就暂停整个 session。`ImageAnalysis` 本身不依赖 Surface，但由于和 `Preview` 绑定在一起，被连带暂停。

### 辅助因素：缺少诊断日志

原有的代码在 analyzer 入口、图像转换、运动检测结果、亮屏调用等关键节点均无日志输出，无法快速定位问题发生在哪一阶段。

## 解决方案

### 核心方案：移除 Preview use case，只绑定 ImageAnalysis

不依赖 `PreviewView` 的 Surface，相机 pipeline 独立于屏幕状态运行。

**修改内容：**

1. **`DoorbellService.kt` — 移除 Preview 绑定**
   - 删除 `previewUseCase: Preview?` 字段
   - 删除 `Preview.Builder()` 创建和配置
   - 删除 `_surfaceProvider` / `setSurfaceProvider` 配套机制（Preview 向 Service 传递 SurfaceProvider 的通道）
   - `bindToLifecycle` 只传入 `imageAnalysisUseCase`，不再传入 `previewUseCase`

2. **`DoorbellService.kt` — 新增 `previewBitmap` StateFlow**
   - companion 中暴露 `previewBitmap: StateFlow<Bitmap?>`，每帧经过 `processFrame` 时更新
   - UI 通过 `collectAsState()` 观察并展示最新帧

3. **`DoorbellApp.kt` — 预览改为 Image 展示 Bitmap**
   - 移除 `PreviewView`，改用 Compose `Image` 组件
   - 从 `DoorbellService.previewBitmap` 读取最新的 Bitmap 帧并显示
   - 预览帧率与服务检测帧率一致（监控模式 ~3fps，录制模式 ~30fps）

4. **全程添加诊断日志**
   - `[FRAME]` — analyzer 入口，确认帧是否到达
   - `[BITMAP]` — 图像转换结果，确认是否成功
   - `[MOTION]` — MotionDetector 判决结果
   - `[SCREEN]` — 亮屏锁获取/释放

### 修复后的数据流

```
熄屏 → Preview 不存在 → 无需 Surface → CameraX session 不受影响
  → ImageAnalysis 持续出帧 → [FRAME] 持续输出
    → imageProxyToBitmap → processFrame
      → _previewBitmap.value = bitmap (推送到 UI)
      → MotionDetector.detect() → [MOTION] 日志
        → 检测到运动 → acquireScreenWakeLock()
          → [SCREEN] 日志 → 屏幕自动点亮
            → 继续人形检测 → 触发事件
```

### 对比总结

| 项目 | 修改前 | 修改后 |
|---|---|---|
| CameraX 绑定 | Preview + ImageAnalysis | 仅 ImageAnalysis |
| 预览实现 | PreviewView Surface 渲染 | Bitmap 帧 Image 显示 |
| 熄屏后检测 | ❌ 暂停（Surface 销毁） | ✅ 持续运行 |
| 屏幕刷新率 | 实时（设备帧率） | ~3fps（检测帧率） |
| 依赖 UI Surface | ✅ 是 | ❌ 否 |

对于门铃场景，预览帧率从实时降为 ~3fps 是可接受的——主要功能是运动检测，预览帧用于定位确认检测是否正常工作即可。
